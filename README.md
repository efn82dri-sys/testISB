# سایت سه‌بعدی ISB (گروه ساختمانی بنای پایدار ایران زمین)

این پروژه همان سایت قبلی است، فقط از یک فایل ۲٫۶ مگابایتی به چند فایل مرتب تقسیم شده است.
ظاهر، حرکت دوربین، مکث روی نمای ایزومتریک، زوم و هم‌گامی دستیار با دوربین تغییری نکرده‌اند.
سایت بدون بک‌اند است و مستقیم روی GitHub Pages اجرا می‌شود.

## اجرای محلی (تست روی کامپیوتر)

سایت داده‌ها را با fetch می‌خواند، پس با دوبار کلیک روی index.html کار نمی‌کند.
باید یک سرور محلی بالا بیاورید. داخل پوشهٔ site بنویسید:

```
python -m http.server 8000
```

بعد این آدرس را در مرورگر باز کنید:

```
http://localhost:8000
```

بعد از هر ادیت، صفحه را با Ctrl+Shift+R رفرش کنید تا کش مرورگر پاک شود.

## پنل مدیریت (افزودن و حذف محتوا بدون کدنویسی)

پنل در آدرس /admin/ است و فقط روی هاست PHP کار می‌کند (روی GitHub Pages نه).
فعلاً دو بخش دارد: «کلیپ‌های همایش» و «اعضای تیم». بخش‌های بعدی (پروژه‌ها، گواهینامه‌ها، ...) با افزودن چند خط به admin/schemas.json اضافه می‌شوند.

### نصب روی هاست

۱. همهٔ فایل‌های پوشهٔ site را روی هاست (public_html) آپلود کنید.

۲. بلافاصله این آدرس را باز کنید و رمز ادمین را (حداقل ۱۰ نویسه) تعیین کنید:

```
https://your-domain.com/admin/setup.php
```

بعد از ذخیرهٔ رمز، این صفحه قفل می‌شود. اگر رمز را فراموش کردید، فایل admin/config.php را از هاست حذف کنید و دوباره setup.php را باز کنید.

۳. وارد پنل شوید:

```
https://your-domain.com/admin/
```

۴. پوشه‌های data و assets/images/uploads باید برای PHP قابل نوشتن باشند (معمولاً مجوز 755 کافی است). اگر ذخیره خطای مجوز داد، از پشتیبانی هاست بخواهید.

### کار با پنل

- «افزودن» یک مورد جدید می‌سازد. فرم‌ها هر دو زبان فارسی و انگلیسی را می‌خواهند.
- فلش‌ها ترتیب را عوض می‌کنند. «حذف» مورد را از فهرست برمی‌دارد.
- هیچ تغییری تا زدن «ذخیره و انتشار» در سایت دیده نمی‌شود.
- هر ذخیره یک نسخهٔ پشتیبان می‌سازد (۲۰ نسخهٔ آخر). با «نسخه‌های قبلی» می‌توانید برگردید.
- عکس‌ها فقط JPG، PNG یا WEBP و حداکثر ۸ مگابایت. برای سرعت سایت، عکس را قبل از آپلود تا عرض ۱۶۰۰ پیکسل کوچک کنید.

### امنیت

- رمز به‌صورت هش‌شده ذخیره می‌شود و بعد از ۵ تلاش اشتباه، ۱۵ دقیقه قفل می‌شود.
- فقط فایل‌های فهرست‌شده در schemas.json قابل ویرایش‌اند و هر درخواست ذخیره توکن CSRF دارد.
- عکس‌های آپلودی در پوشه‌ای هستند که اجرای هر اسکریپت در آن ممنوع است.
- حتماً سایت را با HTTPS (SSL) اجرا کنید.
- فایل‌های .htaccess داخل پوشه‌ها را حذف نکنید. روی سرورهای Apache و LiteSpeed (cPanel و DirectAdmin) کار می‌کنند.

### تست پنل روی کامپیوتر خودتان (بدون PHP)

```
python tools/dev_server.py
```

بعد در مرورگر:

```
http://localhost:8000/admin/
```

رمز پیش‌فرض admin12345 است. تغییرات واقعاً در data/*.json نوشته می‌شود.
(قبل از آپلود نهایی، فایل‌های تست مثل data/clips.json و عکس‌های assets/images/uploads را پاک کنید یا برگردانید.)

## صفحهٔ تیم، دپارتمان‌ها و اعتبارنامه

همهٔ این‌ها از پنل ادمین (تب‌های «اعضای تیم»، «دپارتمان‌ها»، «گواهینامه‌ها»، «نظر کارفرمایان») یا مستقیم از فایل‌های data قابل ادیت‌اند.

- **جایگاه «مدیریت»:** هر عضوی که جایگاهش «مدیریت» باشد، بالای صفحه با کارت بزرگ نمایش داده می‌شود (مثلاً مدیرعامل و مدیران دپارتمان‌ها).
- **دپارتمان:** فیلترهای صفحهٔ تیم از دپارتمان‌ها ساخته می‌شوند. دپارتمانی که عضو ندارد نمایش داده نمی‌شود.
- **عکس پرتره:** عمودی (نسبت ۴ به ۵)، حداقل ۸۰۰ پیکسل عرض، پس‌زمینهٔ ساده و یکسان برای همه. عکس کوچک‌تر از ۴۸۰ پیکسل کشیده نمی‌شود و داخل یک دایره نمایش داده می‌شود.
- **پروفایل هر نفر:** با کلیک روی کارت، کشوی پروفایل باز می‌شود: عکس، سمت، معرفی، حوزه‌های تخصص، تحصیلات و لینک‌ها. بخش‌های خالی نمایش داده نمی‌شوند.
- **عددهای بالای صفحه** (تعداد اعضا، گواهی‌ها، پروژه‌ها، دفاتر همکار) خودکار از داده‌ها شمرده می‌شوند و ثابت نیستند.
- **گواهینامه و نظرها:** فقط مواردی که ثبت کرده‌اید نمایش داده می‌شوند. بخش خالی دیده نمی‌شود. میانگین امتیاز فقط از نظرهای «نمایش در سایت» حساب می‌شود.

## صفحهٔ خدمات

- بالای صفحه «پروژه‌تان در چه مرحله‌ای است؟» با چهار مرحله دیده می‌شود: ایده و طراحی اولیه، طراحی تفصیلی و مدارک، ساخت و اجرا، ساختمان موجود. با انتخاب یک مرحله، خدمات مرتبط روشن و بقیه کم‌رنگ می‌شوند.
- خدمات در سه گروه نمایش داده می‌شوند و با کلیک روی هر کارت، برگهٔ جزئیات باز می‌شود. دکمهٔ «درخواست مشاوره» دستیار ISB را باز می‌کند.
- از پنل ادمین (تب‌های «خدمات» و «گروه‌های خدمات») می‌توانید خدمت اضافه کنید، گروه و مرحله‌هایش را تعیین کنید و آیکن انتخاب کنید. شمارهٔ خدمت خودکار است.
- مرحله‌های پروژه (چهار مورد) در فایل data/services.json بخش stages هستند و از پنل قابل ویرایش نیستند، چون کل صفحه روی همین چهار مرحله طراحی شده است.
- لینک مستقیم به یک خدمت: آدرس صفحه با `#/sv:3` (شمارهٔ خدمت) برگهٔ آن خدمت را باز می‌کند.

## تبدیل مدل Revit به GLB (برای نمایشگر سه‌بعدی پروژه‌ها)

سایت فایل GLB می‌خواند. اگر فقط خروجی IFC دارید، با ابزار tools/ifc_to_glb.py تبدیل کنید (بدون Blender).

### ۱. آماده‌سازی در Revit

- یک نمای سه‌بعدی جدا بسازید و فقط ساختمان، پوسته، سقف و کمی محوطه را نگه دارید. مبلمان، تأسیسات، برش‌ها، نوشته‌ها و لینک‌های اضافه را مخفی کنید.
- در پنجرهٔ IFC export گزینهٔ «Export only elements visible in view» را روشن کنید و همان نما را انتخاب کنید.
- اگر در نسخهٔ Revit شما هست، فرمت IFC4 Reference View معمولاً فایل کوچک‌تر و تمیزتر می‌دهد.
- اگر گزینهٔ Level of Detail را دیدید، روی Low بگذارید.

### ۲. تبدیل (یک بار نصب، بعد یک دستور)

```
pip install ifcopenshell numpy
python tools/ifc_to_glb.py mehregan.ifc mehregan.glb
```

اسکریپت:
- دسته‌های غیرضروری مثل مبلمان، تأسیسات، فضاها و اجزای بسیار ریز را حذف می‌کند.
- مدل را به سه لایهٔ structure، envelope و details می‌چیند تا بعداً روی سایت دکمهٔ روشن/خاموش لایه‌ها ساخته شود.
- مدل را وسط می‌گذارد، جهت محور را برای وب اصلاح می‌کند و تعداد مثلث‌ها را تا سقف ۲۵۰ هزار کم می‌کند.
- حجم و تعداد مثلث هر لایه را گزارش می‌دهد.

حجم IFC و حجم GLB به هم ربطی ندارند. IFC پر از اطلاعات غیرهندسی است و GLB فقط هندسه و رنگ دارد.
هدف: ۳ تا ۸ مگابایت برای هر پروژه (حداکثر ۱۰).

اگر نتیجه هنوز سنگین بود:

```
python tools/ifc_to_glb.py mehregan.ifc mehregan.glb --budget 120000 --min-size 0.3
```

برای دیدن اندازهٔ هر لایه بدون ساخت فایل:

```
python tools/ifc_to_glb.py mehregan.ifc --report
```

برای اطمینان از سالم بودن ابزار، بدون IFC:

```
python tools/ifc_to_glb.py --demo demo.glb
```

## کلیپ‌های همایش (درباره ما)

- کلیپ را اول در آپارات آپلود کنید، بعد در پنل ادمین (تب «کلیپ‌های همایش») فقط لینک آن را (مثل https://www.aparat.com/v/xxxxx)، یک تصویر پوستر و مدت کلیپ را ثبت کنید.
- سایت پوستر را به‌عنوان پیش‌نمایش نشان می‌دهد و با کلیک، پخش‌کنندهٔ آپارات داخل صفحه باز می‌شود. کلیپ ریلز (عمودی) در قاب عمودی پخش می‌شود.
- «پخش پشت‌سرهم»: بعد از پایان «مدت کلیپ» که ثبت کرده‌اید، کلیپ بعدی شروع می‌شود. پخش‌کنندهٔ آپارات پایان ویدیو را به سایت خبر نمی‌دهد؛ پس این کار فقط با همان مدت ثبت‌شده انجام می‌شود و باید مدت را درست وارد کنید.
- اگر هیچ کلیپی ثبت نشده باشد، این بخش دیده نمی‌شود.
- قبل از انتشار، یک کلیپ واقعی را تست کنید؛ آدرس پخش‌کنندهٔ آپارات (embed) در کد سایت از روی لینک ساخته می‌شود.

## پایداری در عمل و برج سرو سبز

- «آزمایشگاه پایداری» پنج طرح شماتیک دوحالته دارد. این‌ها تصویر آموزشی‌اند و نتیجهٔ پروژهٔ مشخصی نیستند (زیر هر طرح هم همین نوشته شده است).
- «برآورد سریع رتبه»: امتیاز هر حوزه × وزن آن، تقسیم بر جمع وزن‌ها. آستانهٔ سطح‌ها (سبز بیش از ۸۰، طلایی ۶۰ تا ۸۰، نقره‌ای ۵۰ تا ۶۰، فیروزه‌ای ۴۰ تا ۵۰) همان است که در متن خود سایت آمده بود. این یک ابزار آموزشی است و جایگزین ارزیابی رسمی نیست.
- وزن‌ها در data/sarv.json (پنل ادمین، تب «وزن‌های سرو سبز») هستند. فعلاً جمع آن‌ها ۱۰۶ است؛ حتماً با جدول رسمی سرو سبز تطبیق دهید. validate.py هم برای همین هشدار می‌دهد.

## صفحهٔ تماس

- راه‌های ارتباط (اینستاگرام، واتساپ، تماس) از «پیج‌های اینستاگرام» و «شماره‌های تماس» در پنل ساخته می‌شوند. شمارهٔ اول دکمهٔ تماس است و شماره‌ای که «در واتساپ فعال است» داشته باشد دکمهٔ واتساپ می‌دهد.
- نمایش زندهٔ کل پیج اینستاگرام عملاً ممکن نیست (نیاز به API و تنظیمات پیچیده دارد و بدون فیلترشکن هم ممکن است خالی بماند). به‌جایش «پست‌های پیج‌ها» را از پنل اضافه کنید: عکس، متن کوتاه و لینک پست. حداکثر ۶ پست آخر هر پیج نمایش داده می‌شود و سریع بدون فیلترشکن لود می‌شود.
- می‌توانید چند پیج اضافه کنید (مثلاً پیج تیم و پیج شرکت) و برای هر مسئول یک کارت تماس مستقیم بسازید.

## چک‌لیست قبل از انتشار نهایی

۱. در انتهای index.html عبارت YOUR_CODE (GoatCounter) را با کد خودتان عوض کنید.
۲. وزن‌های سرو سبز را با جدول رسمی تطبیق دهید.
۳. روی هاست: setup.php را باز کنید و رمز ادمین بگذارید، بعد یک کلیپ، یک عضو تیم و یک پست آزمایشی اضافه و حذف کنید.
۴. اطلاعات واقعی را وارد کنید: عکس و بیوگرافی نفرات، گواهینامه‌ها، کلیپ‌ها، شماره‌ها و پست‌های اینستاگرام.
۵. سایت را روی یک گوشی واقعی (اندروید و آیفون) و یک مرورگر دسکتاپ باز کنید. به نمای ایزومتریک، مکث و زوم دوربین، چراغ‌های خیابان و پخش کلیپ آپارات دقت کنید.
۶. `python validate.py` را اجرا کنید و همهٔ خطاها را برطرف کنید.
۷. HTTPS (SSL) را فعال کنید.

## ادیت متن‌ها

هر متن فارسی یک نسخهٔ انگلیسی دارد. هر دو را با هم عوض کنید.

مثال: عنوان یک پروژه در projects.json:

```
"title": { "fa": "مجتمع مسکونی مهرگان", "en": "Mehregan Residential Complex" }
```

- متن‌های عمومی صفحه‌ها (درباره ما، تماس، منو، فوتر): fa.json و en.json
- پروژه‌ها: projects.json
- خدمات و دوره‌های آموزشی: services.json
- تیم: team.json
- شش ایستگاه مسیر پایداری: chapters.json
- نام هفت بخش شهرک: town.json (بخش sections)
- پیام‌های دستیار هنگام اسکرول: guide.json (بخش guide)
- متن فرم تیکت دستیار: guide.json (بخش assistantTexts)

نکته: داخل متن‌ها از علامت " استفاده نکنید، چون JSON خراب می‌شود. به‌جایش از « » استفاده کنید.

## اضافه کردن پروژه جدید

۱. عکس کاور را داخل assets/images/projects/نام-پروژه/ بگذارید (مثلاً cover.jpg).

۲. مسیر عکس را به images.json اضافه کنید:

```
"/projects/my-project/cover.jpg"
```

۳. یک آیتم شبیه آیتم‌های قبلی به projects.json اضافه کنید (slug باید یکتا باشد و coverImage همان مسیر عکس).

۴. اجرا کنید و خطاها را ببینید:

```
python validate.py
```

## اعتبارسنجی داده‌ها

```
python validate.py
```

این فایل بررسی می‌کند:
- JSONها خراب نباشند
- fa.json و en.json کلید به کلید برابر باشند
- هر متن دوزبانه هر دو زبان را داشته باشد
- همهٔ عکس‌های اشاره‌شده روی دیسک وجود داشته باشند
- تعدادهایی که سایت به آن‌ها وابسته است درست باشند (۶ فصل، ۷ بخش شهرک، ...)

قبل از هر آپلود به GitHub یک بار اجرایش کنید.

## استقرار روی GitHub Pages

۱. یک مخزن (repository) بسازید.

۲. محتوای داخل پوشهٔ site را (نه خود پوشه را) در ریشهٔ مخزن آپلود کنید. فایل index.html باید در ریشه باشد. فایل .nojekyll هم باید کنارش باشد.

۳. در مخزن: Settings ← Pages ← Source را روی Deploy from a branch بگذارید، شاخه main و پوشه / (root) را انتخاب کنید.

۴. بعد از یکی دو دقیقه سایت در این آدرس بالا می‌آید:

```
https://USERNAME.github.io/REPO/
```

اگر دامنهٔ شخصی دارید، در همان صفحهٔ Pages وارد کنید.

## آمار بازدید (GoatCounter)

در انتهای index.html عبارت YOUR_CODE را با کد سایت خودتان از goatcounter.com عوض کنید:

```
data-goatcounter="https://YOUR_CODE.goatcounter.com/count"
```

## تنظیمات دستیار و تیکت

بالای فایل js/mascot.js یک بخش تنظیمات (CFG) هست:

```
endpoint:''   آدرس سرویس دریافت تیکت (POST، JSON)
email:''      ایمیل برای ارسال نسخهٔ تیکت
guide:true    توضیح دادن کاراکتر هنگام اسکرول (false = خاموش)
tipDwell:550  مدت توقف روی هر بخش تا کاراکتر شروع به صحبت کند (میلی‌ثانیه)
```

## چیزهایی که نباید دست بخورند

- نسخهٔ three.js در index.html باید 0.150.1 بماند. ظاهر صحنه به رفتار همین نسخه وابسته است.
- ترتیب لود فایل‌ها در js/main.js مهم است: i18n، ui، scene، camera، mascot، guide.
- ترتیب فایل‌های css در index.html مهم است: fonts، base، layout، mascot.
- ثابت‌های دوربین در js/camera.js هستند: نمای کامل با key(0)، ضریب نرم‌سازی اسکرول 5.5 و ضریب دنبال کردن دوربین 9.
- در js/guide.js تابع gPos() باید با منطق دوربین در camera.js یکی بماند تا دستیار با دوربین هم‌گام باشد.

## اگر سایت خالی لود شد

- پیام «سایت لود نشد»: فایل را با file:// باز کرده‌اید؛ از python -m http.server استفاده کنید.
- بعد از ادیت داده، سایت لود نمی‌شود: احتمالاً JSON خراب است. python validate.py را اجرا کنید یا کنسول مرورگر (F12) را ببینید.
- روی GitHub Pages عکسی نمی‌آید: حروف بزرگ و کوچک نام فایل‌ها مهم است (Cover.jpg با cover.jpg فرق دارد).
